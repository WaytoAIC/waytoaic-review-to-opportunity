# 问题与决策卡

## 问题证据卡

1. 可观察的问题，及尚未证实的根因假设。
2. 人群、场景、需求、当前解决方案；原文没写就未知。
3. 支持与反例记录 ID、原句、变体、日期、购买/Vine 信息。
4. 具体条件：地面、工具/设置、边角或整体、使用时长、洗前后等，按问题相关性填写。
5. 图片/视频：未查看 / 已查看 / 无法读取；观察、能支持、不能支持；静态照片通常不能证明动态故障。不能仅凭外观保证真实性。
6. 记录数与独立人数分开，分母、样本筛选方式和重复来源写清；同一人多个 ASIN 或跨源重复不能多算。
7. 证据强弱与目标款适用程度分别解释，保留反例、未知条件和替代解释。
8. 状态与下一步：资料不足 / 值得验证 / 业务确认真问题；最后一种须有实际业务确认，不让脚本代判。

## 五类决策卡

| 类型 | 必须交代 | 额外验证 |
|---|---|---|
| new_product | 人群、未满足需求、整个产品概念、与已有方案差异 | 市场需求、竞争供给、支付意愿、技术及成本可行性 |
| product_iteration | 改什么、保留什么、为什么、代价 | 同款实测、结构/批次/条件归因 |
| listing | 哪个位置、回应哪个顾虑、建议表达 | 当前页面、实物能力和后续表现；不制造未实测承诺 |
| search_terms | 评论种子词与检索词分开；拓展/观察/待验证排除 | 搜索相关性、真实查询与投放表现；负面评论不自动产生否词 |
| asin_targeting | 核实的 ASIN、竞争或互补关系、切入理由 | 商品页面、目标人群/规格/价格、可投放性与测试结果 |

每张卡带问题 ID、支持证据、反例影响、动作、验收方法、待补项、署名 waytoaic。

数据不足时可给候选概念/检索种子/验证方案，标 hypothesis；缺具体 ASIN 就明确没有可交付的定投名单。业务效果只能在行动后据实评估。

试验方案写明成功判据 acceptance，与试验步骤 verification 分开。判据未由业务确认时标建议；test_plan 状态只表示有方案，不暗示实物、资源或阈值已就绪。
